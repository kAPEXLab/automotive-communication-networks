# ACK Error Demonstration

## Objective

Show that a CAN/CAN FD transmitter requires acknowledgement from at least one other active CAN node.


## Setup

Use two PCAN-USB FD modules connected as shown below:

```text
PCAN-USB FD #1  <---- CAN FD bus ---->  PCAN-USB FD #2
```

Configure both nodes in PCAN-View:

```text
Mode:             CAN FD
Nominal bit rate: 500 kbit/s
Data bit rate:    2 Mbit/s
```

---

## Verify Normal Communication First

From **Node 1**, transmit the following CAN FD frame:

```text
ID:      801
Length:  8
Type:    CAN FD
BRS:     ON
RTR:     OFF
Data:    11 22 33 44 55 66 77 88
```

Expected observation on **Node 2**:

```text
ID 0x801 received successfully.
```

---

## Fault Creation

Keep **Node 1** active.

Close PCAN-View for **Node 2**.

Now only one active CAN controller remains on the bus.

```text
Node 1 = Active transmitter
Node 2 = Offline / not initialized
```

---

## Transmit from Node 1

From **Node 1**, send the following cyclic CAN FD frame:

```text
ID:      802
Length:  8
Type:    CAN FD
BRS:     ON
RTR:     OFF
Cycle:   100 ms
Data:    11 22 33 44 55 66 77 88
```

---

## Expected Observation

Possible PCAN-View status on **Node 1**:

```text
Error Passive Warning
Bus warning
Bus-Off
Transmit error
```

---

## Explanation

A CAN/CAN FD transmitter expects acknowledgement from at least one other active CAN node.

In this experiment:

```text
Node 1 transmits a frame.
Node 2 is offline.
No active receiver provides ACK.
Node 1 detects ACK error.
Transmit error counter increases.
Node may enter Error Passive or Bus-Off.
```

---

## Important Point

A CAN node cannot successfully transmit alone on a normal CAN bus.

At least one other active CAN node must correctly receive the frame and provide ACK.

---

## Filtering Note

Do not confuse ACK with application-level filtering.

```text
A node may ignore a received message in software.
But if its CAN controller receives the frame correctly, it still provides ACK.
```

Therefore:

```text
Application ignores message  -> ACK may still happen
No active receiver on bus    -> ACK does not happen
```

---

## Recovery Procedure

Follow these steps to recover:

```text
1. Stop cyclic transmission on Node 1.
2. Reopen PCAN-View for Node 2.
3. Close and reopen Node 1 if required.
4. Reinitialize both nodes with the same CAN FD settings.
5. Verify normal communication again.
```

Use the following CAN FD settings on both nodes:

```text
Mode:             CAN FD
Nominal bit rate: 500 kbit/s
Data bit rate:    2 Mbit/s
```

---

## Recovery Test Frame

From **Node 1**, transmit:

```text
ID:      803
Length:  8
Type:    CAN FD
BRS:     ON
RTR:     OFF
Data:    11 22 33 44 55 66 77 88
```

Expected observation:

```text
Node 2 receives the frame successfully.
```

---

## Key Observations

```text
1. A CAN/CAN FD transmitter needs ACK from another active node.
2. If no ACK is received, transmit errors increase.
3. Repeated ACK errors may cause Error Passive or Bus-Off.
4. Closing the receiver node is enough to create an ACK error.
5. After removing the fault, reinitialize the interface if required.
```

---

## Discussion Points

```text
1. Why does a transmitter need ACK?
2. What happens if only one node is active on the bus?
3. Is ACK generated by application software or CAN controller hardware?
4. Can a node ACK a message even if the application ignores that ID?
5. Why is Bus-Off a protection mechanism?
```

---

## Conclusion

CAN/CAN FD communication requires at least one active receiver to acknowledge transmitted frames.

Without ACK, the transmitter detects errors and may enter **Error Passive** or **Bus-Off**.
